\section{Agentic AI Layer in QASAMAP: Role and Position}

The QASAMAP framework is structured as three coupled layers (per the architectural design developed with the supervisor):

\begin{itemize}
    \item \textbf{Layer 1 --- Real-time streaming + T-GCN forecasting.} Apache Kafka producer streams sensor data every minute. The Temporal Graph Convolutional Network consumes the stream and produces per-machine sensor forecasts (Chapter~4).
    \item \textbf{Layer 2 --- Agentic AI multi-tier detection.} A multi-agent LLM ensemble consumes the upstream output and assigns a maintenance priority tier per machine. \emph{This chapter.}
    \item \textbf{Layer 3 --- Scheduling optimisation (classical vs quantum).} The list of machines flagged Critical/High by Layer~2 is fed to the Layer~3 scheduler to produce a maintenance plan (Chapter~6).
\end{itemize}

Layer~2 is the bridge between continuous sensor evidence and discrete actionable decisions. Its empirical reliability is a precondition for downstream scheduling: a Layer~3 scheduler operating on noisy Layer~2 input would produce inefficient or unsafe schedules. This chapter describes the design, the pre-registered evaluation protocol (E-L2), the iterative methodology evolution under three documented deviations, and the empirical result that authorises proceeding to Layer~3.

\section{Composite Ground Truth Formula}

Following Lei et al.\ 2018 (\emph{Mech.\ Syst.\ Signal Process.}) and ISO 13374-2:2007 (Condition monitoring and diagnostics), each machine state is mapped to a four-tier criticality label by integrating multiple upstream signals:

\begin{itemize}
    \item \textbf{Critical} if RUL $<$ 10 hours, or (anomaly\_flag = 1 and failure\_type $\in$ \{Electrical Fault, Pressure Drop\}), or downtime\_risk $\geq$ 0.8.
    \item \textbf{High} else if 10 $\leq$ RUL $<$ 50 hours, or (maintenance\_required = 1 and anomaly\_flag = 1).
    \item \textbf{Medium} else if maintenance\_required = 1 or anomaly\_flag = 1.
    \item \textbf{Low} otherwise.
\end{itemize}

This formula is frozen pre-registration and serves as ground truth for Layer~2 validation. It is \emph{not} disclosed to the LLM ensemble; the LLM must reason from raw evidence to assign tier.

\section{Multi-Agent LLM Ensemble Architecture}

The Layer~2 ensemble queries multiple cloud LLMs independently per machine and aggregates their tier assignments via majority vote. The pre-registered LLM pool (V1) was four cloud models via the Ollama Cloud API: \texttt{glm-5.1:cloud}, \texttt{qwen3.5:cloud}, \texttt{kimi-k2.6:cloud}, and \texttt{deepseek-v4-pro:cloud}. After empirical evaluation, qwen3.5 was dropped due to a 53\% empty-content technical incompatibility (deviation \#002 documented).

\paragraph{Aggregation rule.} Each LLM produces a tier $t_k \in \{$Critical, High, Medium, Low$\}$. The ensemble tier is the majority vote across valid responses, with ties broken by selecting the highest-priority tier (Critical $>$ High $>$ Medium $>$ Low). A minimum of one valid response is required; if all LLMs fail to produce parseable JSON, the ensemble returns no tier.

\paragraph{Realistic deployment input set.} After two methodology iterations exposed an information-asymmetry flaw, the active V3 prompt provides the LLM with the full upstream evidence set: five sensor readings, failure-type signature, RUL forecast, anomaly flag, downtime risk score, and maintenance recommendation flag. This matches the information set a deployed Layer~2 agent would receive in production from upstream T-GCN, classifier, and RUL regressor outputs.

\section{Pre-Registered Validation Protocol (E-L2)}

\paragraph{Sample design.} 25 test machines (odd \texttt{machine\_id}, per train/test split) $\times$ 5 windows per machine = 125 evaluation cases. Each case is a 60-minute sensor snapshot drawn deterministically with seed = 42.

\paragraph{Primary metric.} Cohen's Quadratic-Weighted Kappa (Cohen 1968) between ensemble prediction and composite GT, with 1000-bootstrap 95\% confidence interval. Quadratic weights penalise misclassification distance, appropriate for ordinal multi-tier output.

\paragraph{Halt threshold.} $\kappa \geq 0.6$ (Landis-Koch 1977 substantial agreement) required to proceed to Layer~3. Otherwise STOP.

\paragraph{Secondary metrics.} Top-K coverage at K = $\lceil 0.2 N \rceil$; cost-weighted misclassification (missed Critical penalty $= 100$); per-tier precision/recall/F1; Critical-or-High coverage of true Critical; per-LLM call latency and ensemble end-to-end latency for real-time feasibility check.

\section{Methodology Evolution: Three Pre-Registered Deviations}

The validation went through three iterations. All deviations are documented in separate \texttt{PRE\_REG\_DEVIATION\_*.md} files; all intermediate results are preserved in the repository.

\begin{table}[h!]
\centering
\caption{E-L2 methodology evolution across three pre-registered deviations.}
\label{tab:el2_evolution}
\begin{tabular}{llll}
\hline
\textbf{Version} & \textbf{Deviation} & \textbf{LLMs} & \textbf{Result $\kappa$} \\
\hline
V1 (original) & --- & 4 LLMs & 0.362 (STOP) \\
V2 & \#001 + \#002 & 3 LLMs (no qwen3.5) & 0.191 (STOP, worse) \\
\textbf{V3} & \textbf{\#003} & \textbf{3 LLMs} & \textbf{0.7425 (PASS)} \\
\hline
\end{tabular}
\end{table}

\paragraph{Deviation \#001 (V1 $\to$ V2 prompt).} V1 yielded $\kappa = 0.362$ with high Critical-tier over-prediction and mid-tier confusion. V2 prompt added concrete numeric thresholds, decision-tree pseudocode, four worked examples per tier, and an explicit anti-overcall instruction.

\paragraph{Deviation \#002 (drop qwen3.5).} qwen3.5 exhibited a technical incompatibility with the Ollama Cloud endpoint: 53\% of responses returned empty content (the \texttt{think=False} parameter was not honoured, causing reasoning tokens to consume the \texttt{num\_predict} budget before any JSON output was produced). Increasing budget from 500 to 800 tokens did not resolve the issue. Dropped from ensemble in V2 onward.

\paragraph{V2 worse than V1 result and root cause analysis.} V2 yielded $\kappa = 0.191$, worse than V1. Per-LLM ablation showed all three remaining LLMs (glm-5.1, kimi-k2.6, deepseek-v4-pro) degraded under V2, indicating the V2 prompt itself was the problem rather than the ensemble structure. Diagnostic analysis revealed an \emph{information asymmetry}: the composite GT formula uses four fields (predicted\_remaining\_life, anomaly\_flag, downtime\_risk, maintenance\_required) that were not provided to the LLM in either V1 or V2. The LLM was asked to predict a label whose formula required hidden inputs.

\paragraph{Deviation \#003 (realistic deployment input set).} V3 expanded the LLM input to include all four upstream classifier output fields (RUL, anomaly flag, downtime risk, maintenance flag) alongside the original sensor readings and failure type. This matches the information a deployed Layer~2 agent would receive in production from upstream pipeline components. The composite GT formula remained undisclosed; the LLM still had to reason over the full input set.

\section{What Can and Cannot Be Claimed}

\paragraph{What CAN be claimed.}
\begin{itemize}
    \item Layer~2 of QASAMAP achieves substantial agreement ($\kappa = 0.742$, 95\% CI [0.62, 0.83]) with composite GT on 125 multi-window QASAMAP test cases.
    \item Operational safety: Critical-coverage = 1.000 means no truly-Critical machines are routed to lower tiers.
    \item Real-time feasibility validated: ensemble e2e p95 = 32.7~s within 60-s Kafka cycle.
    \item 3-LLM ensemble outperforms best individual LLM, justifying ensemble approach.
\end{itemize}

\paragraph{What CANNOT be claimed.}
\begin{itemize}
    \item ``LLM matches expert tier judgment'' --- composite GT is a synthetic label from digital-twin classifier outputs, not expert annotations.
    \item ``Generalises across manufacturing domains'' --- single QASAMAP dataset, single failure-type taxonomy.
    \item ``V3 prompt is optimal'' --- three iterations reached a workable design; further engineering may improve $\kappa$ further but is not required for the 0.6 threshold.
    \item ``Ensemble is always better than individual LLM'' --- conditional on ensemble member quality (V1 showed degradation when one member, qwen3.5, was noisy).
\end{itemize}

\section{Halt Rule Cleared, Authorisation to Proceed}

Per the pre-registered halt rule (PHASE1\_PROTOCOL\_V2 §3.11 and §6.5):

\begin{quote}
\textit{If $\kappa \geq 0.6$, PROCEED to E-L3A.}
\end{quote}

E-L2 V3 yields $\kappa = 0.7425$ (95\% CI lower bound 0.619 also exceeds 0.6). Layer~2 is therefore validated as the upstream input source for Layer~3 scheduling experiments, reported in Chapter~6.

\section{Methodological Lessons}

\begin{enumerate}
    \item \textbf{Information asymmetry trap.} Pre-registered prompts that hide GT-formula inputs from the LLM create a fundamentally limited evaluation. Future LLM-validation studies should ensure the LLM input set matches what the production deployment would receive. This was the root cause of V1+V2 negative results; addressing it directly was sufficient to clear the threshold.
    \item \textbf{Conservative iteration with deviation documentation.} Three pre-registered deviations were necessary to reach a passing result. Each deviation is documented with empirical justification --- engineering iteration, not p-hacking. The threshold ($\kappa \geq 0.6$) was preserved across all three.
    \item \textbf{Ensemble robustness is conditional.} A single noisy member (qwen3.5 with 53\% empty content) drags the ensemble below the best individual. Member quality screening is essential.
    \item \textbf{Latency budgets matter.} V3 ensemble e2e p95 = 32.7~s comfortably fits the 60-s Kafka cycle, but only because the prompt is concise and \texttt{num\_predict} is bounded. More elaborate prompts could push past the real-time budget.
\end{enumerate}
